# ui
- For multi-pane tools, make panes collapsible and width-adjustable by the user. Confidence: 0.70
- Use icon buttons instead of text buttons for clear and copy actions in tool toolbars. Confidence: 0.70
- Wants visual and structural consistency within a toolbar: when adding a new control, reuse the existing pattern's markup/styling for that control type ("apply the previous style") rather than introducing a new look. Confidence: 0.6
- Prefer plain standalone buttons over collapsed dropdown/popover menus for a small set of related actions; each button carries its own icon. Confidence: 0.65
- Prefer a single "Save" action that always prompts the user for the destination filename, rather than separate "Save" (silent default-named download) and "Save As" buttons. Confidence: 0.6
- When changing UI colors/accents, explicitly check what accent to use for each theme and verify the result across all supported themes (app has ~19 data-theme variants) rather than just the currently active one; pick accent tokens that stay visible in every theme. Confidence: 0.7
- UI state indicators (checked vs. unchecked, selected vs. unselected) must be clearly, visibly distinct — flags muted or washed-out states as a defect ("too muted, can't see the difference"). Confidence: 0.6
- Reports UI issues by pasting a screenshot with a terse comment on what looks wrong; expects the agent to visually analyze the image before changing code. Confidence: 0.7
- Search result ranking must prioritize matches on the feature/tool name over matches in the description: name matches rank first, description matches are the secondary key, and recency may only break ties — it must never pull a description-only match above a name match. Confidence: 0.7
- Expects long, nested list/config surfaces (e.g. the settings page) to be filterable via a search input instead of requiring the user to scroll and expand categories to find an item. Confidence: 0.5
- Requires uniform control sizing in a toolbar row: buttons and dropdown/summary triggers sitting side by side must render the exact same height/box, and mismatched heights are reported as a defect ("not uniform in size? should be uniform in height"). Confidence: 0.7
- Wants text inputs standardized app-wide: every form control (text field, select, dropdown trigger) should share one control style — same height, padding, font size, border, radius, background — instead of page-local one-offs falling back to browser/reset defaults; unstyled or differently-styled textfields are reported as a defect ("textfield isn't standardized"). Confidence: 0.65
- Requires uniform horizontal spacing between toolbar controls: every item in a toolbar row should be separated by the same gap (the flex `gap`), and one-off margins that double the spacing around a single control are a defect to fix. Confidence: 0.6
- Expects the global command palette (⌘K) to be the single entry point for everything, including app settings — individual settings should be indexed as results named with their section prefix ("Settings: Theme") and selecting one should jump straight to that setting. Confidence: 0.6
